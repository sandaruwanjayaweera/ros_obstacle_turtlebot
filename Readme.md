# ROS 2 CAM/DENM Messaging for TurtleBot



An experimental ROS 2 communication layer for exchanging cooperative-awareness and collision-warning information between mobile robots.



This repository was created as a building block for a TurtleBot experiment in which OptiTrack provides localization and custom ROS 2 messages carry robot state and obstacle-related information. The current revision contains the custom interfaces and example publisher/subscriber nodes. It does \*\*not\*\* yet include the OptiTrack bridge, a TurtleBot navigation stack, or a complete obstacle-avoidance controller.



> \*\*Project status:\*\* early research prototype. The CAM and DENM structures are custom ROS 2 representations inspired by ETSI ITS messages; they are not a standards-compliant ETSI ITS protocol implementation.



## Features



- Custom ROS 2 message definitions for Cooperative Awareness Messages (CAMs) and DENM collision warnings.

- Python publisher and subscriber nodes built with `rclpy`.

- Synthetic 3D position generation for testing the CAM data path.

- A simplified local-coordinate/GPS conversion utility.

- Additional experimental CAM/DENM message definitions for future extensions.

## ROS 2 nodes and topics



| Executable | Function | Interface | Topic | Current publish period |
| :--- | :--- | :--- | :---: | :---: |
| `talker` | Publishes a CAM with synthetic position data | `tutorial_interfaces/msg/CAM` | `/CAM` | 0.5 ms |
| `listener` | Receives and logs CAM fields | `tutorial_interfaces/msg/CAM` | `/CAM` | — |
| `talker_cw` | Publishes a fixed DENM collision-warning example | `tutorial_interfaces/msg/DENMCW` | `/topic` | 1 ms |
| `listener_cw` | Receives and logs DENM collision-warning fields | `tutorial_interfaces/msg/DENMCW` | `/topic` | — |



The queue depth is currently set to `10` for all publishers and subscribers.

The high publication rates are useful for stress testing but can produce a

large amount of terminal output. Reduce the timer periods in the publisher

source files when running an interactive demonstration.



\## Interfaces generated by the build



The `tutorial\_interfaces` package currently generates the following interfaces:



- `tutorial\_interfaces/msg/CAM`

- `tutorial\_interfaces/msg/DENMCW`

- `tutorial\_interfaces/msg/Num`

- `tutorial\_interfaces/srv/AddThreeInts`



Other definitions in `tutorial\_interfaces/msg/`, including `CAMEXT` and the

refuel/acceptance DENM variants, are experimental files and are not yet listed

in `rosidl\_generate\_interfaces()`.



## Prerequisites



\- A supported ROS 2 installation

\- Python 3 and `rclpy`

\- `colcon`

\- `rosdep`

\- ROS interface-generation packages (`rosidl\_default\_generators` and

&#x20; `rosidl\_default\_runtime`)



The repository does not currently pin or document a tested ROS 2 distribution.



## Installation



Create a ROS 2 workspace and clone the repository into its `src` directory:



```bash

mkdir -p \~/ros2\_ws/src

cd \~/ros2\_ws/src

git clone https://github.com/sandaruwanjayaweera/ros\_obstacle\_turtlebot.git

cd \~/ros2\_ws

```



Source your ROS 2 installation, install declared dependencies, and build the

packages. Replace `<distro>` with your installed ROS 2 distribution, such as

`humble` or `jazzy`.



```bash

source /opt/ros/<distro>/setup.bash

rosdep install --from-paths src --ignore-src -r -y

colcon build --symlink-install --packages-up-to py\_custom

source install/setup.bash

```



When opening a new terminal, source both the ROS 2 installation and the

workspace before running a node:



```bash

source /opt/ros/<distro>/setup.bash

source \~/ros2\_ws/install/setup.bash

```



\## Usage



\### CAM publisher and subscriber



Start the CAM subscriber:



```bash

ros2 run py\_custom listener

```



In another sourced terminal, start the CAM publisher:



```bash

ros2 run py\_custom talker

```



The publisher increments a synthetic local `x`, `y`, and `z` position, converts

it to scaled geographic fields, and publishes a `CAM` message on `/CAM`.



Inspect the interface or topic with:



```bash

ros2 interface show tutorial\_interfaces/msg/CAM

ros2 topic info /CAM

ros2 topic echo /CAM

```



### DENM collision-warning publisher and subscriber



Start the DENM subscriber:



```bash

ros2 run py\_custom listener\_cw

```



In another sourced terminal, start the DENM publisher:



```bash

ros2 run py\_custom talker\_cw

```



The example publishes fixed `DENMCW` field values on `/topic` and logs each

message at the subscriber.



Inspect the interface or topic with:



```bash

ros2 interface show tutorial\_interfaces/msg/DENMCW

ros2 topic info /topic

ros2 topic echo /topic

```



Stop any node with `Ctrl+C`.



## Current limitations



- Position and collision-warning values are synthetic or hard-coded.
- OptiTrack input and TurtleBot motion-control integration are not included.
- The project has no launch files or parameter files.
- Topic names, station IDs, QoS settings, and publication rates are not exposed as ROS parameters.
- The coordinate conversion is a simplified approximation and should not be used where geodetic accuracy is required.
- Several experimental message files are present but are not generated by the current CMake configuration.
- Automated tests cover only the default Python lint templates; functional ROS tests are not yet included.



## Suggested next steps

- Subscribe to OptiTrack pose data and populate CAM fields from live robot position, velocity, and heading.
- Connect received CAM/DENM data to the TurtleBot obstacle-detection and navigation logic.
- Replace hard-coded values with ROS parameters and provide launch files.
- Rename generic nodes and topics to application-specific names.
- Register the remaining custom interfaces in `CMakeLists.txt` as they become supported.
- Add functional tests, continuous integration, and a documented ROS 2 support matrix.
